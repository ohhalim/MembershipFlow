### 여기 없는 파일

같은 날 replay 를 세 번 돌렸고 저장소에는 03 만 넣었다.

- `compare-replay-20260922-01.jsonl` — 헤더에 조건 필드(`llm_available`, `scope`)가 없다
- `compare-replay-20260922-02.jsonl` — 헤더 `replay_file` 에 실행자의 절대 경로가 들어갔다

셋의 경로 판정은 완전히 같다. 로직을 바꾸지 않았고 세 파일의 route 결정을 직접
대조해 확인했다. 달라진 것은 헤더 메타데이터뿐이라 03 이 앞의 둘을 그대로 포함한다.

**지운 것이 아니다.** 01 과 02 는 로컬 보존 브랜치에 그대로 있다. 저장소에 실행자
홈 경로를 넣지 않으려고 배포 범위에서만 뺐다. 원본 보존과 배포 범위는 별개다.

원본은 수정하지 않는다. 출력은 배타 생성(`open(..., "x")`)이라 기존 파일을
덮어쓰지 못한다. 재실행은 새 파일명을 쓴다.

### 이 표를 읽을 때 붙는 조건 두 가지

경로 결정은 제품과 같은 `classify()` 를 그대로 부른다. rule_route 순서도 Jev
실패·저confidence 폴백도 제품 코드가 판단한다. 다만 두 가지가 제품과 다르다.
2026-09-22 에 제품 경로와 직접 대조해 확인한 것이다.

**1. replay 에는 Gemini 가 없다(`llm=None`).** Jev 가 기권하면 제품은 Gemini 로
떨어지는데 replay 는 `classify` 의 기본값 KNOWLEDGE 로 떨어진다. 12건 중 1건이
여기 걸린다 — `"그거 왜 실패했어?"`(confidence 0.42). 대조 실행에서 제품 조건일
때 이 1건만 판정이 갈렸다. **그래서 위 9/12·11/12 는 Gemini 폴백이 없는 조건의
값이고, 제품 조건에서 그 1건이 어디로 갈지는 측정되지 않았다.**

**2. 여기서 비교하는 것은 분류 단계의 route 다.** 제품의 최종 route 는 그 뒤에
한 번 더 바뀔 수 있다. `"현재 구독자 수는?"` 은 분류상 METRIC 이지만
`answer_metric` 이 날짜를 못 정해(`resolve_target_date` 가 "현재" 를 모른다)
CLARIFY 로 끝난다. **위 일치율은 최종 답변 정확도가 아니다.**

두 조건은 결과 파일 헤더에도 `llm_available` 과 `scope` 로 남는다.

## 관측한 것

**1. rule_route 키워드가 설명 질문을 가로챈다.** `_OUT_OF_SCOPE_HINTS` 의 "환불",
`_METRIC_HINTS` 의 "현재" 가 부분 문자열로 걸린다.

- `"환불 처리 방식은 어떻게 구현되어 있어?"` → `OUT_OF_SCOPE` (거절)
- `"현재 코드에서 구독 만료를 어떻게 판단해?"` → `METRIC` (지표 조회)

두 건 모두 코드를 찾아 답할 질문이다. 이건 Jev 와 무관한 **기존 코드의 결함**이고,
분류기를 바꾼다고 고쳐지지 않는다. `rule_route` 가 먼저 도는 한 Jev 는 이 질문을
보지도 못한다(`jev_after_rules` 가 9/12 에 그친 이유).

**2. 순서를 뒤집으면 저 2건이 풀리지만 검증된 설정이 아니다.** `before_rules` 는
11/12 인데, 미검토 라벨 12건 위의 숫자다. 뒤집으면 모든 질문이 외부 호출을
타므로 지연·비용·장애 노출이 함께 늘어난다. 기본값은 `off` 로 뒀다.

**3. "12/12" 는 confidence 를 무시한 수치였다.** 공급사 문서의 예시 임계값
0.5 를 적용하면 `"그거 왜 실패했어?"` (confidence 0.42) 는 기권 대상이 된다.
어댑터는 이 경우 판단을 기존 경로에 넘긴다. 그래서 위 표의 9/12·11/12 는
12/12 보다 낮다. 임계값 0.5 는 **문서 예시를 그대로 쓴 값이고 우리 질문 분포에서
측정한 값이 아니다.**
