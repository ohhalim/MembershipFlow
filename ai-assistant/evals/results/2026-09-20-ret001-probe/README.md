# ret-001 후보 누락 원인 구분 (2026-09-20)

전체 깊이 진단(`2026-09-20-vector-full-depth`)에서 tuning 10건 중 ret-001 만 후보
20 밖이었다. 정답 청크 `Subscription > isActiveAt` 의 vector 순위가 85/317 이었고
원인은 미확정으로 남겼다. 이 진단이 그 후보 원인을 가른다.

## 방법

같은 정답 청크(`5f12d365…`)를 겨냥한 질문을 **한 번에 하나씩만** 바꿔 순위를 다시
잰다. 인덱스·모델·깊이는 고정이다.

- 인덱스 `mf-ai-chunks-64460aa92eba4887a09aa7011522857d` (317청크)
- `BAAI/bge-m3` `5617a9f61b02…`, vector 단일, depth 317
- `code_sha` `9551f14d9b8e`
- ES read-only. 평가셋·라벨·alias 변경 없음.
  아래 질문들은 **진단용 문자열이고 평가셋에 넣지 않았다**

## 결과

## 읽히는 것

**영문 토큰의 유무가 원인이 아니다.** `ko_distinct` 는 영문 토큰이 하나도 없는
순수 한국어인데 10위다. 같은 청크, 같은 모델, 같은 인덱스다. 한국어 질문이
한글이 0자인 코드 청크에 도달하지 못한다는 설명은 이 한 줄로 무너진다.

**질문 길이도 주된 원인이 아니다.** `longer` 는 길이만 늘렸고 28위로 올라왔지만
상위 20에 java 청크가 여전히 0개다. 경쟁 구도가 그대로다.

**남는 설명은 어휘 경쟁이다.** ret-001 의 단어(구독·이용 가능·판정·기준)는 같은
기능을 설명하는 한국어 문서 청크의 어휘와 그대로 겹친다. 이 코퍼스 317청크 중
문서가 269개이고 그중 48개가 '구독' 을 담고 있다. 전부 그럴듯한 후보라 코드 청크
하나를 밀어낸다.

같은 언어로 **상황을 구체적으로** 서술해 그 일반 어휘를 피하면(`ko_distinct`)
경쟁이 사라지고 10위로 올라온다. 반대로 일반 어휘를 더하면(`code_hint`:
"메서드 구현 코드") 159위로 더 내려간다. 문서가 구현을 설명하는 말과 겹쳐서다.

영문 토큰을 넣으면 올라오는 것(`state_token` 4위, `symbol` 1위)은 원인이 아니라
경쟁을 우회하는 지름길이다. 해당 토큰이 문서 청크에는 드물기 때문이다.

## 이 진단이 말하지 않는 것

- 정답 청크 1개, 변형 9개의 관측이다. 통계가 아니다
- 다른 실패 사례(ret-002 20위, ret-004 19위)에 같은 설명이 적용되는지는
  확인하지 않았다
- 대응책(질의 재작성, hybrid 가중치, 청크 보강)은 무엇도 시험하지 않았다
- ret-001 의 **라벨은 여전히 적절하다.** `isActiveAt` 이 판정 로직이 맞다.
  바뀐 것은 원인 해석이지 정답이 아니다
- 평가셋은 `reviewed=false` 그대로다
