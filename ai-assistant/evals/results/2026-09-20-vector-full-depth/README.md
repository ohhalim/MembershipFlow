# vector 전체 깊이 진단 (2026-09-20)

얕은 실행(2026-09-19-pinned-tuning)은 "후보 20 밖"까지만 말할 수 있었다. 21위와
300위는 대응이 다른데 둘이 구분되지 않았다. 코퍼스가 317청크라 질문당 한 번
depth=317 로 검색하면 전체 순위를 얻는다.

이번 10건은 기대 근거가 모두 색인에 존재함을 먼저 확인했고(경로 suffix 규칙으로
일치), 그래서 이 실행에서는 모든 None 이 숫자가 됐다. 색인에 없는 근거가 섞인
질문 집합에서는 같은 방법으로도 None 이 남는다.

## 조건

깊이별 수치는 **한 번 받은 랭킹을 잘라서** 계산한다. 깊이마다 재검색하면 질의

## 확인 사항

- **얕은 실행 재현**: 10건 모두 상위 20 chunk_id 순서가 이전 실행과 완전히 일치.
  @5 0.55 와 @20 0.9 도 이전 vector top5 0.55 / candidate20 0.90 과 같다
- **동점 없음**: 10건 모두 317개 점수가 전부 서로 다르다. 경계(@5/@20/@50/@100)에서도
  동점이 없으므로 순위가 임의로 흔들릴 여지는 이번 관측에 없다
- **비교 입력 동일**: 얕은 실행과 `cases_sha256`(`875197103cfae873…`),
  `physical_index`(`mf-ai-chunks-64460aa9…`), `embedding_revision`(`5617a9f6…`)이
  모두 같다. 실행 후 별도로 대조했고, 이후 재실행에서는 스크립트가 다르면 중단한다

## 보존된 JSON 의 필드명 정정

`results.json` 의 `cases[].shallow_top20_rank_of_expected` 는 **이름과 달리 얕은 실행의
top5 기준 순위**다. 값의 출처가 `matched_ranks` 인데 그건 k=5 로 자른 결과다.
근거: ret-009 의 `최초 결제` 는 전체 깊이에서 9위인데 이 필드에는 `None` 으로 있다.
top20 기준이었다면 9가 들어갔어야 한다.

실행이 끝난 JSON 은 그대로 둔다. 스크립트는 이후 실행부터
`shallow_top5_rank_of_expected` 로 기록한다. 상위 20 일치 비교
(`reproduces_shallow_top20`)는 chunk_id 20개 순서를 직접 대조하므로 이 오해와 무관하게
올바르다.

## 읽히는 것

- 20 -> 50 으로 깊이를 늘려도 얻는 것이 없다 (0.9 -> 0.9). 21~84위 구간에
  정답이 있는 문항이 하나도 없기 때문이다
- 후보 20 밖은 ret-001 하나뿐이고 순위는 85위다. 전체 317 중 27% 지점이라
  "표현이 전혀 안 된다"고 볼 근거는 아니지만, 현재 설정인 후보 20 밖인 것은 분명하다
  (깊이를 늘렸을 때의 지연은 측정하지 않았다. 비용 판단의 근거는 여기 없다)
- 순위 분포가 양극단이다. 10건 중 5건이 1위, 나머지는 8위 이상이다. 2~3위가 없다

## 이 진단이 말하지 않는 것

- ret-001 이 85위인 **원인**은 확정하지 않았다. 질문 길이, 코드 청크의 한글 부재,
  '구독' 문서 청크와의 경쟁 등은 아직 가설이고 이 실행으로 구분되지 않는다
- ret-001 의 `isActive()` 를 대체 정답으로 채택하지 않았다. wrapper 이고 판정 로직
  자체를 담고 있지 않다. 라벨 검토는 사람 몫으로 남긴다
- ret-002(20위)/ret-004(19위)는 후보 안에서의 순위 손실로 분류한다
- keyword/hybrid 는 이번 범위가 아니다. vector 단일 모드만 측정했다
- held_out 은 실행하지 않았다. tuning 10건은 `reviewed=false` 초안이다
