## 독립성의 의미

AI 작성 여부와 독립성은 별개. 사람 검토는 정답의 타당성 확인이고, held-out 격리는
검색 설정 선택에 문항·결과를 사용하지 않는 절차다. 정답 검토를 위해 읽는 것만으로
자동 탈락하지 않는다. 결과를 보고 튜닝에 활용하면 이후 같은 문항의 점수는 최종
독립 검증 근거로 사용하지 않는다. 기존 5건은 이미 개발에 활용돼 회귀 점검용으로만 사용.

신규 20건은 현재 코드/문서에서 답할 수 있는 합성 표본이다. 코드 10건, 운영 문서
10건으로 구성했으며 실제 사용자 질문 분포를 대표하지 않는다. Subscription 메서드와
배포 문서에 집중되어 있다. 정답 청크 비중복은 새로움을 확인하는 보조 지표이며
주제 독립성이나 누출 부재를 보증하지 않는다. 이전 모든 실험 질문과의 의미적 중복은
별도 검토 대상. 실제 Slack 질문을 수집·비식별화해 후속 평가셋을 보강할 수 있다.

## 사람 검토 기준

1. 질문이 명확하고 저장소 근거로 답할 수 있는가
2. 예상 답이 코드/문서와 일치하는가 (문서 기반 질문은 실제 운영 상태와 구분)
3. 근거가 충분한가. 필요한 복수 청크는 모두 포함했는가
4. 범위 제외가 질문을 부당하게 축소하거나 정답에 맞춰 만든 조건은 아닌가
5. 동일하게 충분한 대체 근거가 있는가. 현재 스키마는 대체 정답 OR가 아닌 필수 근거 AND이므로
   대체 근거를 단순 추가하지 말고 질문을 좁히거나 평가 계약을 먼저 검토

`reviewed`는 문항별 사람 검토 상태다. AI의 검토·사용자의 포괄적 작업 허락을 사람의
정답 검토로 바꾸지 않는다. 승인한 ID만 true로 변경하며 승인 범위와 날짜 기록.
기존 tuning 문항도 정답 검토를 마치면 reviewed=true가 될 수 있다.

## 실행 전 동결

- 기본 baseline: 현재 제품 hybrid 검색 설정. 평가 러너의 candidate depth와 제품 검색 깊이가
  다를 수 있으므로 같은 설정인지 먼저 확인. 기존 vector candidate20 실험과 혼동 금지
- 사전 지표: Recall@5, MRR@5, 모든 필수 근거 충족률, 문항별 결과, 지연
- 20건은 예비 검증 규모. 기존 #350의 Recall@1/MRR@10 합격 기준 충족으로 대체하지 않음
- 사람 검토 후 라벨 해시, 코드 SHA, 물리 인덱스, corpus fingerprint, 임베딩 revision,
  검색 k/candidate depth/모드를 별도 manifest에 고정
- 조회 대상 인덱스에 기대 청크가 없다면 누락을 기록. 편의상 문항을 제외하지 말 것
- 최종 검증용 실행은 reviewed=true 문항만, --allow-draft 없이 수행
- 최초 결과를 본 뒤 수정/튜닝한 구성은 새 검증셋 필요. 결과 원본 덮어쓰기 금지

## 라벨 변경과 과거 점수

ret-006 필수 근거가 1개에서 2개로 변경됐다. 같은 질문이어도 Recall 분모가 바뀌므로
이전 수치와 직접 비교 불가. 구성 간 비교는 양쪽 모두 동일한 새 라벨로 채점.
과거 candidates/returned에 필요한 ID·경로가 보존돼 있으면 오프라인 재채점 가능 여부부터
확인하며, 없으면 동일 corpus/모델/설정에서 재실행. 단순 라벨 변경을 검색 개선으로 보고하지 않는다.
