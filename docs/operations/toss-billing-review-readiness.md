# TossPayments 자동결제 심사 준비 점검

점검일: 2026-08-22

## 기준

- TossPayments 연동 가이드 v2 `자동결제(빌링) 결제창 연동하기`
- TossPayments 계약 안내 `토스페이먼츠 결제제품`
- 자동결제 사용 조건: 추가 리스크 검토 및 계약
- 라이브 키 발급 조건: 전자결제 계약 및 카드사 심사 완료

## 현재 구현 확인

| 항목 | 상태 | 근거 |
| --- | --- | --- |
| 월간·연간 판매 플랜 | 확인 | `GET /api/v1/subscriptions/plans`, 월 10,000원·연 90,000원 |
| 카드 본인인증 결제창 | 확인 | TossPayments SDK v2 `requestBillingAuth()` |
| 빌링키 발급 | 확인 | `POST /v1/billing/authorizations/issue` |
| 최초 결제 승인 | 확인 | 빌링키 저장 후 `POST /v1/billing/{billingKey}` |
| 결제 응답 검증 | 확인 | `orderId`, 금액, `DONE`, `BILLING`, `paymentKey` 검증 |
| 중복 콜백 제어 | 확인 | 결제 시도 상태, 회원·시도 행 잠금, 최초 결제 멱등키 |
| 승인 응답 유실 복구 | 확인 | 같은 `orderId` 승인 결과 조회 |
| 빌링키 보관 | 확인 | AES 암호화 저장, 원문 로그 제외 |
| 정기결제 스케줄 | 확인 | 다음 결제일 도래 구독 일별 처리 |
| 해지 후 추가 과금 차단 | 확인 | `CANCELLED` 상태는 정기결제 대상에서 제외 |
| 외부 호출 제한 시간 | 확인 | 연결 5초, 응답 65초; 자동결제 최대 60초 기준 반영 |
| 실패 코드 전달 | 확인 | 콜백 실패 시 내부 오류 메시지 대신 허용된 오류 코드 전달 |

## 심사 전 차단 항목

### 홈페이지·구매 흐름

- 비회원 구매 흐름 미제공
  - 현재 `/my/subscription`은 Google 로그인 이후 접근 가능
  - TossPayments 홈페이지 심사 안내의 비회원 구매 가능 조건과 불일치
  - 비회원 결제와 목표가 알림 계정 연결 정책 결정 필요
- 사업자 정보 푸터 미등록
  - 상호, 사업자등록번호, 대표자, 사업장 주소, 전화번호 필요
  - 사업자등록증과 홈페이지 표기의 일치 확인 필요
- 결제 직전 고지 부족
  - 현재 버튼 문구는 카드 등록이지만 콜백 직후 최초 결제 수행
  - 선택 플랜 금액, 최초 결제, 자동 갱신 주기, 해지 조건, 약관 동의 표시 필요
- 약관의 연간 플랜·환불 기준 누락
  - 현재 약관은 1개월 자동 갱신만 기재
  - 월간·연간 갱신, 최초 결제 시점, 해지 효력, 청약철회·환불 기준 정리 필요

### 운영 준비

- 테스트 MID로 아래 흐름의 결제내역 확인 필요
  1. 로그인
  2. 월간 구독 선택
  3. 카드 인증
  4. 최초 결제
  5. 구독 `ACTIVE` 반영
  6. 목표가 등록
  7. 시세 수집
  8. 알림 이력 저장 및 WebSocket 수신
  9. 구독 해지
  10. 다음 결제 대상 제외
- 라이브 MID는 자동결제 계약이 연결된 키인지 확인 필요
- 결제 실패·카드 만료 시 카드 재등록 경로 확인 필요
- 고객 문의·환불 처리 연락처와 운영 절차 등록 필요

## 승인과 코드 검증의 경계

- 코드와 테스트는 결제 흐름의 기술적 준비 상태만 검증
- 전자결제 계약, 업종·상품 리스크 검토, 홈페이지 심사, 카드사 심사 결과는 TossPayments 판단
- `NOT_SUPPORTED_METHOD` 발생 시 자동결제 계약이 연결된 MID·클라이언트 키 확인
- 심사 통과를 보장하는 표현 사용 금지

## 남은 개선 대상

- 정기결제 상태 선점·외부 호출·결과 반영의 짧은 트랜잭션 분리
- 정기결제 전용 멱등키 저장 및 재시도 결과 대조
- 해지된 구독의 미사용 빌링키 삭제 정책 및 실패 재처리
- 이메일·앱 푸시 등 오프라인 목표가 알림 채널
